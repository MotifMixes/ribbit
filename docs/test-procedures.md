# Test procedures

## Automated (no user files needed; runs in CI)

```sh
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

## CPU oracle fixtures

Fixtures in `crates/ribbit-cpu/tests/vectors/` are generated by the GNU ARC toolchain and committed:

```sh
python scripts/gen-cpu-vectors.py --toolchain path/to/arc-gnu/bin
```

Full-BIOS decoder sweep (local only):

```sh
arc-elf32-objdump -D -b binary -m ARC600 -EL --adjust-vma=0x40000000 bios.bin > bios.dis
RIBBIT_BIOS_OBJDUMP=$PWD/bios.dis cargo test -p ribbit-cpu --release --test objdump_oracle -- --nocapture
```

## With your own images (local only)

The repository never contains firmware or game images. Point environment variables at your files instead:

```sh
# PowerShell: $env:RIBBIT_CART = "C:\path\to\cart.bin"
RIBBIT_CART=/path/to/cart.bin cargo test -p ribbit-memory --test user_images -- --nocapture
```

For the SpongeBob 500-11002 dump, this test also checks the directory layout and the 29 SWF movies observed during
research.

## CLI checks

```sh
cargo run -p ribbit-desktop -- info --cart cart.bin            # identify an image
cargo run -p ribbit-desktop -- info --firmware bios.bin
cargo run -p ribbit-desktop -- inspect-cart cart.bin --dump 256
cargo run -p ribbit-desktop -- headless --firmware bios.bin --cart cart.bin \
    --max-instructions 1000000 --dump-frame frame.ppm
cargo run -p ribbit-desktop -- run --firmware bios.bin --cart cart.bin
```

`headless` exit codes: `0` = step limit, breakpoint or halt, `2` = CPU error (unsupported, illegal or unpredictable
instruction), `1` = usage/load error. `--trace FILE` writes every instruction; `--tail N` prints the last N on exit.

Logging: `RUST_LOG=ribbit::boot=info,ribbit::bus=trace` (logs go to stderr).

## Timer / boot-progress procedure (local only, needs your BIOS dumps)

```sh
# Milestone tests, separately per BIOS: the 10 ms waits (v1.5); LCD init, framebuffer DMA + vector 0x12,
# timer vectors 0x19/0x1A/0x1E, the format-3 switch with no CPU error (v1.5 and v2.1); and straps = 0
# reproducing "LcdMPI::Init can't find config rsrc" in VRAM (v1.5 and v2.1). ~11 s each in release.
RIBBIT_BIOS_DIR=$PWD/roms/bios cargo test -p ribbit-core --release --test user_bios -- --nocapture

# Inspect the wait yourself: --trace interleaves instructions and peripheral accesses.
cargo run --release -p ribbit-desktop -- headless --firmware roms/bios/155-10072-a.bin \
    --max-steps 3000000 --trace tools/analysis/v15.trace --tail 20
grep -m5 'mmio.*0x0180d80' tools/analysis/v15.trace
```

## Experimental touch procedure (local only; EXPERIMENTAL, UNVERIFIED model)

```sh
# Includes v15/v21_experimental_touch_* (~80 s each in release, run in parallel).
RIBBIT_BIOS_DIR=$PWD/roms/bios cargo test -p ribbit-core --release --test user_bios

# Calibrate by hand: five presses on the targets (raw ADC = pixel * 0x7F0 / 159, MAME's mapping).
P="--touch-press 1700,300,128,128 --touch-press 3000,300,128,1917 --touch-press 4300,300,1917,1917 \
   --touch-press 5600,300,1917,128 --touch-press 6900,300,1022,1022"
ribbit headless --firmware roms/bios/152-11265_2.1.bin --cart <your cart> --experimental-mame-touch $P \
    --max-steps 1920000000 --coverage cov.txt --dump-frame frame.ppm
# Skip calibration instead (MAME's default straps): --straps 0x63FFFFFF
# Break only after N steps: --arm-breakpoints-after N --breakpoint 0x400283d6   (v2.1 PlayMovie log call)
```

Every report from such a run starts with `!! EXPERIMENTAL`. `--coverage` writes each PC with the cycle it was first
executed; the report lists every distinct unmapped access with its first cycle, and cartridge read counts.

## Speed (local only)

```sh
# Steps per second and a state digest that must not change when optimising.
cargo run --release -p ribbit-core --example bench -- roms/bios/152-11265_2.1.bin 200000000
# Sampling profile (Windows, no admin needed).
CARGO_PROFILE_RELEASE_DEBUG=true cargo run --release -p ribbit-core --example profile -- roms/bios/152-11265_2.1.bin
```

Reference digests after 200 M steps (straps 0x63FFFFFF, no cartridge), current model: v1.5 `5b97c1cdbe4f0df3`, v2.1
`fa1296791d776f49`. They change whenever the emulated hardware model changes (not for pure speed work). Add
`noskip` as a third argument to run every idle-loop iteration; the digest must not change.

## Playing (local only)

`local/play.toml` (git-ignored) points at your BIOS, cartridge and save files:

```sh
target/release/ribbit --config local/play.toml run
```

Mouse = stylus (EXPERIMENTAL touch model), arrows = d-pad, Z = A, X = B, H = Hint, Enter = Pause,
Backspace = Home; controllers via gilrs. Saves are autosaved and written when the window closes. F5/F9 = state slot
1, hold ` = rewind. `ribbit-gui.exe` is the same app without a console; to try it without touching your settings,
point `APPDATA` at a scratch folder.

Release zip: `python -I scripts/package-release.py` (checks that only the two programs and README.txt are packed).
The release build is profile-guided (`scripts/pgo_build.py`, skip with `--no-pgo`): it trains an instrumented
`bench` on the user's dumps (Leapster 2 Pet Pals and Cosmic Math, original Leapster Sonic X, L-MAX Cars 2) and
needs `llvm-profdata` of rustc's LLVM major version. Measured 2026-10-16: 10.6% (Pet Pals) and 15.9% (Cosmic
Math) faster per instruction, state digests identical.

## MAME differential check (local only)

Needs an official MAME build (0.289 used) and `leapster.zip` in the ROM path. Compares the first-visit order of
PCs; registers neither emulator models are stubbed with MAME 0.289's constants (debug only).

```sh
python scripts/compare-mame-trace.py --mame tools/mame0289/mame.exe --rompath . \
    --bios uni15 --firmware roms/bios/155-10072-a.bin --stop 40073d74
python scripts/compare-mame-trace.py --mame tools/mame0289/mame.exe --rompath . \
    --bios us21 --firmware roms/bios/152-11265_2.1.bin --stop 40039102
```

```sh
rustup target add aarch64-linux-android aarch64-apple-ios
cargo check --target aarch64-linux-android -p ribbit-core
cargo check --target aarch64-apple-ios -p ribbit-core
```
